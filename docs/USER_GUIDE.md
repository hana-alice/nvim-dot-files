# 使用手册：把这套 Neovim 当 UE / Android IDE 用

> 这份文档写给**使用的人**。它讲「我想做某件事，该按什么」，不讲实现。
> 内部机制见 [`architecture/overview.md`](architecture/overview.md)，踩过的坑见
> [`CONSTRAINTS.md`](CONSTRAINTS.md)，完整按键表见
> [`ue_lazyvim_cheatsheet.md`](ue_lazyvim_cheatsheet.md)。
>
> 约定：`<leader>` 是空格键。所有操作都能只用键盘完成。

## 1. 只需要记住的五个键

其它的都可以从这五个键里找到，不用背。

| 按键 | 做什么 |
|---|---|
| `<leader>P` | **命令中枢**。列出当前平台能做的所有事，可以输入文字搜索；每一项后面标着它自己的快捷键，用几次就记住了。 |
| `<leader>uu` | **当前目标**。查看并切换 项目 / 平台 / 设备 / 包名。 |
| `<F5>` | **运行**。没在调试时：跑当前平台的完整循环；正在调试时：继续执行。 |
| `<S-F5>` | **停止**调试。 |
| `<leader>uk` | **修复**。刚才有操作失败时，执行它建议的修复命令。 |

忘了别的键时：`<leader>P` 搜，或 `<leader>?` 打开速查表。

## 2. 第一次使用

1. 打开工程里的任意文件，或执行 `:UESetProject`。
2. `<leader>uu` → 选 **Platform**（例如 `Android Development`）。
3. 如果是 Android：同一个面板里选 **Device** 和 **Package**。
   包名会从设备上已安装的应用里列出来供选择，不需要手打。
4. 执行 `:UEPrepare` 生成编译数据库和索引（第一次比较久，之后是增量的）。
5. 执行 `:UEDoctor` 检查环境。打 ✗ 的行上按回车，会直接执行对应的修复。

设备是「这个 Neovim 窗口自己的选择」，不会影响你开的另一个 Neovim，重启后需要重新选。
项目、平台、包名会记住。

## 3. 日常循环（Android）

**改代码 → 在手机上看到效果**，一个键：

- `<F5>`（或 `<leader>ux`）：编译 SO → 热替换到设备 → 在调试器下启动应用。
  任何一步失败都会立刻停下并告诉你停在哪一步。
- 不想带调试器：`:UEAndroidIterate nodebug`。

也可以分步做：

| 按键 | 步骤 |
|---|---|
| `<leader>us` | 只编译 SO（不打 APK） |
| `<leader>uq` | 把 SO 热替换到设备（应用保持停止） |
| `<leader>ul` | 启动应用（不带调试器） |
| `<leader>ui` | 安装 APK |
| `<leader>ub` | 完整构建 |

> SO 热替换要求设备上已经装了**同一套 Java/JNI 基线**的 APK。换了引擎版本或改了 Java 层，
> 先 `<leader>ui` 重新安装一次。

## 4. 调试

| 想做的事 | 按键 |
|---|---|
| 附加到正在运行的应用 | `<leader>da` |
| 从第一行代码开始调试（应用启动即停住） | `<leader>dl` |
| 下 / 取消断点 | `<F9>` 或 `<leader>db` |
| 继续 / 暂停 | `<F5>` / `<F6>` |
| 单步：跳过 / 进入 / 跳出 | `<F10>` / `<F11>` / `<S-F11>` |
| 运行到光标处 | `<leader>dt` |
| 看光标下变量的值 | `<leader>dh` |
| 求值一个表达式 | `<leader>de` |
| 加入监视 | `<leader>dw`（UE 类型用 `<leader>dW`） |
| 调用栈上 / 下一帧 | `<leader>dk` / `<leader>dj` |
| 条件断点 / 日志断点 / 清空断点 | `<leader>dB` / `<leader>dL` / `<leader>dC` |
| 停止 | `<S-F5>` |

调试中可以随时下新断点，不需要重新附加。

**附加失败时**：提示会先说明问题出在哪一层（工具链 / 连接 / 系统权限 / 调试引擎 / 符号），
再给处置办法。有现成修复命令的，按 `<leader>uk` 直接执行。想在附加前先查一遍，用
`:UEDAPPreflight`。

**应用重启后**想接着调：`:UEDAPReattach`（沿用上次的设备、包名和符号）。

## 5. 看日志、查崩溃

| 想做的事 | 按键 |
|---|---|
| 应用日志窗口 | `<leader>ug` |
| 调试时的 logcat 面板 | `<leader>d4` |
| 最近一次崩溃的调用栈（带源码位置） | `<leader>uX` |
| 历史通知 | `<leader>uN` |

在 logcat 面板里：

| 按键 | 作用 |
|---|---|
| `<CR>` | 跳到这一行里提到的源码位置 |
| `gl` | 切换最低显示级别（全部 → Debug → Info → Warn → Error） |
| `gx` | 符号化最近一次崩溃 |

`<leader>uX` 会把结果放进 quickfix 列表：能对上符号的帧可以直接回车跳到源码，
对不上的帧原样保留并标 `[unresolved]`。符号库按**构建 ID**匹配，和调试器用的是同一份；
如果提示没有匹配的符号库，说明设备上装的包和本机当前构建不是同一次构建。

## 6. 读代码、找东西

| 想做的事 | 按键 |
|---|---|
| 跳到定义 | `gd` |
| 全工程搜索文本 | `<leader>/` |
| 在当前模块 / 插件里找文件 | `<leader>uo` |
| 找文件 / 最近打开 | `<leader><leader>` |
| 侧边栏（缓冲区 / 符号 / 诊断） | `<leader>v` 开头的一组键 |
| 文件树 | `<leader>fe` |

`gd` 对 C++ 走编译器级的语义跳转；索引没准备好时会明确告诉你，而不是跳到一个猜的位置。

### 找回以前做过的事

| 想找回 | 按键 |
|---|---|
| **所有「以前的」入口**（搜索、文件、跳转、命令、通知、旧 quickfix、git 记录） | `<leader>fh` |
| 以前搜过的词 | `<leader>sH` |
| 上次的搜索结果（原样恢复） | `<leader>s/` |
| 上一个任意 picker | `<leader>sR` |
| 最近打开的文件 | `<leader>fr` |
| 光标去过的位置 | `<leader>sj` |

`<leader>sH` 的排序：**真正打开过结果的搜索排在前面**，带次数和多久以前（`3h ×2`）；
按项目分开记，不会混进别的工程的搜索。下面是更早的记录，已经去掉了打字过程中的半截词
（比如搜 `shadebin` 时中途留下的 `shadeb`）。回车即重新搜索。

## 7. 状态栏怎么读

右侧的 UE 段从左到右：

```
UE  <模块范围>  PROJECT  <索引状态>  Q:…  PREP*  <构建结果>  A:<设备>/<包名>  ⏵N
```

| 片段 | 含义 |
|---|---|
| 索引状态 | 索引是否就绪、是否在收敛 |
| `Q:…` | 排队中的索引任务 |
| `PREP*` | `:UEPrepare` 正在跑 |
| `BOK` / `B<数字>` / `BERR` | 最近一次构建成功 / 退出码 / 启动失败 |
| `LOOP✓ 42s` / `LOOP✗` | 最近一次一键循环成功及耗时 / 失败 |
| `A:Pixel 8/game` | Android 当前设备和包名（`no-device` 表示还没选） |
| `⏵3` | 有 3 个后台任务在跑，`<leader>X` 查看或停止 |

左侧模式块后面的 `⏸ DBG` / `▶ DBG` 表示调试会话停在断点 / 正在运行。

## 8. 后台任务

构建、索引、日志读取都在后台跑，不会卡住编辑。

| 按键 | 作用 |
|---|---|
| `<leader>X` | 列出后台任务，选中即停止 |
| `<leader>Xs` | 停止一个（只有一个时直接停） |
| `<leader>XA` | 全部停止（会先确认） |

## 9. 出问题时先看哪里

1. **`:UEDoctor`** —— 工具、项目、平台、设备、包名是否齐全。
2. **`<leader>uk`** —— 刚失败的操作有没有现成修复。
3. **`:UEDAPPreflight`** —— 调试附加会卡在哪一层。
4. **`:UEIndexStatus`** —— 跳转不对、搜不到时看索引状态。
5. **`<leader>uN`** —— 翻回刚才一闪而过的提示。
6. **`:NvimCoreHealth`** —— 编辑器本身的基础功能体检。

常见情况：

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| 附加时提示进程没在运行 | 应用没启动 | `<leader>uk`（改用启动调试），或先 `<leader>ul` |
| 断点是空心的、不命中 | 符号和设备上的包不是同一次构建 | 重新 `<leader>us` + `<leader>uq`，或重装 APK |
| 状态栏显示 `A:no-device` | 这个窗口还没选设备 | `<leader>uu` → Device |
| 提示「所选设备未连接」 | 设备被拔掉/掉线，目标仍是原来那台 | 接回设备，或 `<leader>uk` 选另一台 |
| `gd` 提示索引未就绪 | 还没 Prepare 或正在索引 | 看状态栏；必要时 `:UEPrepare` |
| 搜索结果不全 | 搜索索引过期 | `:UEBuildCsearch` |

## 10. 这套东西的取舍

- **键盘优先**。不做可点击的工具栏和按钮；用「一个可搜索入口 + 状态栏常驻提示」代替。
- **能选就不让你打字**。设备、包名、平台都是列表选择。
- **失败说人话**。先说是哪一层的问题，再说怎么办，能一键修的给一键修。
- **不卡界面**。多等几秒可以接受，编辑器卡住不行。
