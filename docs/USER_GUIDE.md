# 使用手册：把这套 Neovim 当 UE / Android IDE 用

> 这份文档写给**使用的人**。它讲「我想做某件事，该按什么」，不讲实现。
> 内部机制见 [`architecture/overview.md`](architecture/overview.md)，踩过的坑见
> [`CONSTRAINTS.md`](CONSTRAINTS.md)，完整按键表见
> [`ue_lazyvim_cheatsheet.md`](ue_lazyvim_cheatsheet.md)。
>
> 约定：`<leader>` 是空格键。所有操作都能只用键盘完成。

## 1. 只需要记住的六个键

其它的都可以从这些入口里找到，不用背。

| 按键 | 做什么 |
|---|---|
| `<leader>P` | **命令中枢**。列出当前平台能做的事，可以输入文字搜索；每项标出已有快捷键或可执行命令。 |
| `<leader>uu` | **当前目标**。查看并切换 项目 / 平台 / 设备 / 包名。 |
| `<F5>` | **运行**。没在调试时：跑当前平台的完整循环；正在调试时：继续执行。 |
| `<S-F5>` | **停止**调试。 |
| `<leader>uk` | **修复**。刚才有操作失败时，执行它建议的修复命令。 |
| `<leader>wM` | **找回工作窗口**。搜索窗口、隐藏缓冲区、保存结果、任务和日志。 |

忘了别的键时：`<leader>P` 搜，或 `<leader>?` 打开速查表。
**本手册随时可以在编辑器里打开：`<leader>u?` 或 `:UEGuide`**（命令中枢里也能搜到「使用手册」）。

## 2. 第一次使用

1. 打开工程里的任意文件，或执行 `:UESetProject`。
2. `<leader>uu` → 选 **Platform**（例如 `Android Development`）。
3. 如果是 Android：同一个面板里选 **Device** 和 **Package**。
   包名会从设备上已安装的应用里列出来供选择，不需要手打。
4. 执行 `:UEPrepare` 生成编译数据库和索引（第一次比较久，之后是增量的）。
5. 执行 `:UEDoctor` 检查环境。打 ✗ 的行上按回车，会直接执行对应的修复。

设备是「这个 Neovim 窗口自己的选择」，不会影响你开的另一个 Neovim，重启后需要重新选。
项目、平台、包名会记住。

命令中枢会显示缺工程、平台、设备或包名的动作。选择后可进入已有配置入口，再确认继续原操作；
取消不会在稍后启动任务。这里检查选择和当前文件的能力；索引覆盖、设备在线与符号匹配仍需
分别看 `:UEIndexStatus`、`:UEDoctor` 和调试预检。

## 3. 日常循环（Android）

**改代码 → 在手机上看到效果**，一个键：

- `<F5>`（或 `<leader>ux`）：编译 SO → 热替换到设备 → 在调试器下启动应用。
  任何一步失败都会立刻停下并告诉你停在哪一步。
- 不想带调试器：`:UEAndroidIterate nodebug`。
- 停止当前循环：`:UEAndroidIterateStop`；停止后不再进入下一阶段。

每次循环固定开始时的工程、配置、设备和包名，过程中切换只影响下一次。
最后的成功以应用启动或调试附加回应为准。每次仍进入构建检查；部署确认 SO 的 SHA-256
未变时显示复用。尚未启用前端跳过 UBT。

常用组合可用 `:UERunProfileSave` 命名保存，再用 `:UERunProfile` 预览差异、选择应用；
`:UERunProfileDelete` 删除配置。配置包含平台、编译配置、包名及运行方式，不保存设备 serial。
运行方式选 `run` 时，空闲状态 F5 走无调试器循环；调试会话中 F5 继续执行。

也可以分步做：

| 按键 | 步骤 |
|---|---|
| `<leader>us` | 只编译 SO（不打 APK） |
| `<leader>uq` | 把 SO 热替换到设备（应用保持停止） |
| `<leader>ul` | 启动应用（不带调试器） |
| `<leader>ui` | 安装 APK |
| `<leader>ub` | 完整构建 |

> SO 热替换要求设备上已经装了**同一套 Java/JNI 基线**的 APK。换了引擎版本或改了 Java 层，
> 先 `<leader>ui` 重新安装一次。

构建失败时，结束通知会显示首个错误的文件和行号，按 `<leader>uE` 直接跳到源码。
问题列表把 error 排在 warning 前；warning 和其它输出仍保留。没有源码位置的失败会明确提示，
可查看构建输出或结果列表。`<leader>P` 搜「构建错误」也能跳转，`]q` / `[q` 继续浏览当前 quickfix。
打开诊断、符号或文件侧栏不会改变这两个键的目标；`2]q` 可前进两项。
搜索或崩溃分析也使用 quickfix。若已切换结果，先从 `:UEWorkspace results` 选择构建列表，
再用 `]q` / `[q` 浏览；到达边界时会提示，不自动切换列表。语言服务的错误和警告见下文「逐项处理问题」。
后台输出和失败问题列表保留当前编辑焦点；主动打开面板才进入它。首错跳转后用 Ctrl-O 返回。

## 4. 调试

| 想做的事 | 按键 |
|---|---|
| 附加到正在运行的应用 | `<leader>da` |
| 从第一行代码开始调试（应用启动即停住） | `<leader>dl` |
| 下 / 取消断点 | `<F9>` 或 `<leader>db` |
| 继续 / 暂停 | `<F5>` / `<F6>` |
| 单步：跳过 / 进入 / 跳出 | `<F10>` / `<F11>` / `<S-F11>` |
| 运行到光标处 | `<leader>dt` |
| 看光标下变量的值 | `<leader>dh` |
| 求值一个表达式 | `<leader>de` |
| 加入监视 | `<leader>dw`（UE 类型用 `<leader>dW`） |
| 调用栈上 / 下一帧 | `<leader>dk` / `<leader>dj` |
| 条件断点 / 日志断点 / 清空断点 | `<leader>dB` / `<leader>dL` / `<leader>dC` |
| 停止 | `<S-F5>` |

调试中可以随时下新断点，不需要重新附加。
调试界面保留原源码分屏；停止时恢复未被主动改变的阅读位置和比例。调试期间新建、关闭、
调整分屏或编辑文件会保留新的选择；只清理本次调试拥有的窗口。

**附加失败时**：提示会先说明问题出在哪一层（工具链 / 连接 / 系统权限 / 调试引擎 / 符号），
再给处置办法。有现成修复命令的，按 `<leader>uk` 直接执行。想在附加前先查一遍，用
`:UEDAPPreflight`。

**应用重启后**想接着调：`:UEDAPReattach`（沿用上次的设备、包名和符号）。
应用有 PID 却长期附加不完成时，Android 可能把后台实例冻结；先用正常启动入口把应用置前台，
再附加。所选 Android 设备已实测此情形；不需要关闭系统冻结策略。UE 名称和字符串的显示仍有已记录限制。

## 5. 看日志、查崩溃

| 想做的事 | 按键 |
|---|---|
| 应用日志窗口 | `<leader>ug` |
| 调试时的 logcat 面板 | `<leader>d4` |
| 最近一次崩溃的调用栈（带源码位置） | `<leader>uX` |
| 历史通知 | `<leader>uN` |

在 logcat 面板里：

| 按键 | 作用 |
|---|---|
| `<CR>` | 跳到这一行里提到的源码位置 |
| `gl` | 切换最低显示级别（全部 → Debug → Info → Warn → Error） |
| `g/` / `gt` / `g0` | 按内容 / tag 筛选 / 清除内容与 tag 筛选 |
| `gf` / `G` | 暂停或切换跟随 / 跳到最新日志并恢复跟随 |
| `gx` | 符号化最近一次崩溃 |

向上阅读会暂停跟随，新日志不把你拉回底部。切换级别和筛选、隐藏或停止读取后仍能回看
已收集内容。历史最多 12000 行或 8 MiB，发生淘汰或单行截断时面板有提示。

`<leader>uX` 会把结果放进 quickfix 列表：能对上符号的帧可以直接回车跳到源码，
对不上的帧原样保留并标 `[unresolved]`。符号库按**构建 ID**匹配，和调试器用的是同一份；
如果提示没有匹配的符号库，说明设备上装的包和本机当前构建不是同一次构建。

## 6. 读代码、找东西

| 想做的事 | 按键 |
|---|---|
| 跳到定义 | `gd` |
| 查看引用，再决定是否跳转 | `gr` |
| 在头文件和源文件间切换 | `<leader>ch` |
| 预览定义，不离开当前阅读位置 | `:UEPeek` |
| 谁调用了光标处的函数 / 它调用了谁 | `<leader>cI` / `<leader>cO` |
| 按类名、函数名搜索工作区符号 | `<leader>sS` |
| 当前文件符号大纲 | `<leader>ss` |
| 光标处类型的基类 / 派生类 | `<leader>cB` / `<leader>cD` |
| 重命名符号 / code action | `<leader>cr` / `<leader>ca` |
| 全工程搜索文本 | `<leader>/` |
| 在当前模块 / 插件里找文件 | `<leader>uo` |
| 找工作区全部文件 | `<leader><leader>` |
| 找工程文件 / 最近打开的文件 | `<leader>ff` / `<leader>fr` |
| 侧边栏（缓冲区 / 符号 / 诊断） | `<leader>v` 开头的一组键 |
| 文件树 | `<leader>fe` |
| 当前类 / 函数的父级上下文 | `[c`；Ctrl-O 返回 |
| 找回关闭的文件、结果或日志窗口 | `<leader>wM` / `:UEWorkspace` |

`gd` 对 C++ 走编译器级的语义跳转；索引没准备好时会明确告诉你，而不是跳到一个猜的位置。

调用与类型层级需要当前 C++ 文件的 clangd 就绪；选择结果回车跳转，再按相应键继续向上或向下探索。
调用列表即使只有一项也先让你查看；多个类型候选会先让你选择。
以上动作也能在 `<leader>P` 输入「基类」「调用」「符号」找到。
`<leader>ss` 保留当前文件的符号树，可输入名称筛选。文件编辑后，旧大纲不会跳到过期位置；
重新按 `<leader>ss` 获取新大纲。
顶部上下文最多三行；高度不足 20 行的窗口不显示。它辅助阅读源码，宏展开产生的类或函数
仍以符号大纲和编译器导航为准。

### 先查看，再跳转

`:UEPeek` 默认预览定义，也可以指定 `declaration`、`implementation`、`type_definition`
或 `references`。预览中回车在原编辑窗口打开，Ctrl-S 横分屏、Alt-V 竖分屏、Ctrl-T 新标签页；
Esc 取消。只有一个目标也不会跳过预览。Ctrl-Q 保存结果并保持调查面板打开，
之后从 `:UEWorkspace results` 选择查看。`:UEReadCancel` 取消尚未返回的请求或当前预览。

`:UEReadReturn` 返回本次阅读调查的起点，包含光标和原阅读位置；主动改了布局或切换工程时
不会强行恢复。平常的 Ctrl-O / Ctrl-I 仍是跳转历史的后退 / 前进。
请求期间切换文件、窗口或编辑内容后，迟到结果会失效，不替换新窗口里的内容。

想连续追调用或继承关系，用 `:UERelations incoming` / `outgoing` / `base` / `derived`。
右方向键展开，左方向键折叠；列表中也可用 `l` / `h`。Alt-U 选父节点，回车打开节点，
Alt-V 在旁边打开；`:UERelations resume` 回到已经加载的分支。只在展开时查询下一层，
循环、范围限制或请求失败会显示出来。标题的「覆盖未知」表示不能用空列表断言没有调用者或派生类。

### 找文件和搜索内容

文件列表支持 `/` 和 `\` 路径，也可粘贴带引号的文件名。输入
`Source/Game/Alpha.cpp:42:7`，或 `"Source/Space Name.cpp":42:7`，回车打开到指定位置。
行和列都从 1 开始；列是 UTF-8 字节列。Ctrl-V 粘贴，Ctrl-Y 复制当前候选的
`路径:行:列`，Alt-Y 复制绝对路径，Alt-Shift-Y 复制相对路径。

`<leader><leader>` 的工作区全文件列表，以及工作区代码文件列表，首次扫描后使用当前会话的列表快照；
新建或删除文件后，在这些列表内按 F5 刷新。热列表与首次扫描使用同一范围，
全文件入口包含文档、脚本、配置和项目文件，代码专用入口仍只列代码。
超过缓存预算时仍显示完整扫描结果，标题说明未缓存。`<leader>ff` 的工程文件列表和
`<leader>uo` 的模块文件列表不使用这份快照，更新后重新打开列表。

`<leader>/` 搜索工程和引擎里**已索引**的文件。在搜索输入框中，Alt-W 切整词，Alt-C 切大小写敏感，
Alt-R 切字面量 / 正则。Alt-D 选择工程、引擎、当前目录、当前文件或模块范围；
Alt-F 设置包含、排除 glob 和文件扩展名。选择的范围只在已索引文件中生效。
标题显示当前范围和等待、搜索中、无结果、错误或部分结果状态；截断、超时和取消都不会显示为完整搜索。

搜索到一批结果后，Ctrl-G 切到结果筛选，输入文件名或路径继续收窄；原内容查询保留，
再次 Ctrl-G 回到内容查询。候选筛选默认不区分大小写，内容查询的大小写模式单独用 Alt-C 控制。
默认结果平铺；需要文件分组可用 `:UEGrepGroupingToggle`。
字面量结果定位到实际匹配；正则结果没有可靠列位置时标「行定位」，复制位置也只包含路径和行。

需要搜索未索引的文本，用 `<leader>sG` 显式进入 rg；代码范围用 `<leader>sg`。
例如输入 `foo -- -g *.cpp` 限定扩展名；这里不是 shell，不要给 glob 加 shell 引号。
无结果时先检查范围、筛选和状态；索引缺失的 `<leader>/` 会提示准备索引，不会自动改用 rg。

### 重构与 UE 声明

`<leader>cr` / `:UERename` 先显示各目标文件的差异，确认后修改缓冲区，取消保持原文。
预览期间的新输入、文件或工程变化会使结果失效。不会自动保存；提交前可继续审阅和编译。
`<leader>ca` / `:UECodeActions` 展示当前服务器实际返回的操作；编译器提供的修改使用同一预览。
无法预览的命令会单独询问是否直接执行，不会当作可预览修改。
`:UERefactorUndo` 撤销上次整批修改；有后续输入时拒绝覆盖。应用或撤销失败可用
`:UERefactorRecovery` 查看已应用、已恢复和需人工审阅的记录。

C++ 补全可搜 `uproperty`、`ufunction`、`uclass`、`ustruct`、`uenum`、`ulog` 等 UE 片段，
Tab / Shift-Tab 切字段。类和结构需填写所属模块 API，并把 generated header 放在最后一个 include。
`:UENewClass` 可选择现有项目模块和 UObject / Actor / Component，预览头源文件后创建；
不会更改 Build.cs 或创建缺失目录，创建后仍应运行工程 UHT 和编译。

### 替换文本，再检查结果

普通模式把光标放到要修改的词，按 `<leader>sr`：命令行预填当前文件的整词替换，
光标在替换内容的位置。输入新文本后回车，逐个按 `y` 替换、`n` 跳过、`a` 替换剩余、`q` 停止。
按 Esc 取消尚未执行的命令；替换不会自动保存，执行后用 `u` 撤销、Ctrl-R 重做。
替换内容沿用 Vim 的替换语法：`&` 表示匹配到的原文字，要插入字面 `&` 用 `\&`。
也可在 `<leader>P` 搜「替换」进入同一个当前文件动作。

已选文字时，用 `v` / `V` 选择，再按 `<leader>sr`，替换范围是本次选区覆盖的行，
查找内容取自本次选区；同一行上选区之外的相同文字也会参与确认。它按字面查找，
无需把点、斜杠等字符写成正则。想按语义修改符号及引用，用 `<leader>cr` 的预览流程。

`:GrugFar` 保留为独立的多文件磁盘替换工具；它按自己的文件筛选和写入流程执行，
不使用本仓的重构预览和整批撤销保护。`<leader>sr` 始终用于上述当前文件／选区流程。

### UE Editor 测试

`:UETests` 提供发现、筛选运行、结果和失败重跑；也可直接用 `:UETests list`、
`:UETests run <筛选>`、`:UETests results`、`:UETests rerun`。发现和运行会启动命令行 Editor，
可在 Tasks 停止。当前 Windows 入口要求所选引擎已有 Editor 可执行文件及工程所需模块；
不会自动编译或安装。失败有日志和可取得的源码位置，不完整报告不会显示通过。

| 以前搜过的词 | `<leader>sH` |
| 最近一次内容搜索（csearch 或 rg） | `<leader>s/` |
| 上一个任意 picker | `<leader>sR` |
| 最近打开的文件 | `<leader>fr` |
| 光标去过的位置 | `<leader>sj` |

`<leader>sH` 的排序：**真正打开过结果的搜索排在前面**，带次数和多久以前（`3h ×2`）；
按项目分开记，不会混进别的工程的搜索。下面是更早的记录，已经去掉了打字过程中的半截词
（比如搜 `shadebin` 时中途留下的 `shadeb`）。新记录保留查询、来源、范围、大小写、整词、
正则和文件筛选，回车按原条件重跑；工程身份不匹配时拒绝重放。旧记录标出
`legacy: query only; modes unknown`，只保留关键词、原模式未知。`<leader>s/` 恢复最近的真实内容搜索，
不会因上次来自 rg 而打开更早的 csearch。

文件和内容搜索列表中，Ctrl-Q 保存当前结果或多选的子集，成功后回到编辑窗口，保留原侧边栏；
它不会自动打开问题面板。阅读调查面板的 Ctrl-Q 保存后继续保留调查。
用 `<leader>wM` 搜 `Results`，或 `:UEWorkspace results`，再选择要看的结果。
保存最多 5000 行、8 MiB；原生结果历史保留 10 个列表。历史已满且保存会淘汰当前结果时会拒绝，
先显式切换要使用的结果再保存。保存的结果窗口关闭后仍可从这里找回；历史已淘汰则需重新搜索。

想保留这次调查：搜索并筛选结果 → Ctrl-Q 保存 → 日后 `:UEWorkspace results` 选择查看。
想按原范围、模式和筛选再搜索一次：`<leader>sH` 选择记录；只想继续最近一次内容搜索用 `<leader>s/`。

### 管理文件和关闭缓冲区

`<leader>fe` 打开文件树。列表中回车打开文件或展开目录，`h` 收起目录；
`a` 新建，`r` 改名，`m` 输入已有目标目录并移动，`d` 确认后送回收站。
目录操作也会检查已打开的子文件。改名和移动不覆盖已有目标，跨磁盘移动需先另行处理。
仅改变文件名大小写时，先改为一个未占用的临时名字，再改为目标名字。

改名、移动或删除前，先保存受影响文件里的修改；未保存文本会阻止操作。
提示期间编辑内容、切换目录或关闭文件树会取消尚未开始的动作。
语言服务器要求同时修改引用或导入时，本入口会说明无法预览并保留文件；
符号重命名使用 `<leader>cr` 的多文件预览。

改名成功后，在原窗口继续编辑，用 `:w` 正常保存到新路径；原有撤销历史仍可使用。

删除后，冻结的旧文本会保留为未命名的未保存文件，检查后可另存；
操作开始后又编辑或重新保存的版本保持其文件名和状态，不会被旧操作接管。
回收失败或移动后检查发现变化时，会给出对象仍保留的目标或恢复路径，可用 `<leader>uN` 找回提示；
这不表示已自动回滚。先确认原路径没有后来新建的内容，再检查保留的对象、人工移回或另存。
从系统回收站恢复后，也需检查恢复位置，再移回原目录。
若未完成的操作留下额外窗口或标签页，用 `<leader>wM` 检查内容后再关闭。

`<leader>bc` 智能关闭当前文件或面板；`<leader>bd` 关闭文件缓冲区并保留窗口布局。
文件有修改时可以保存、放弃或取消；确认之后又出现新编辑会保留文本并提示重新检查。
若卸载回调产生新文本，文本保留在未命名缓冲区，可从 `<leader>wM` 或 `:UEUnsaved` 找回并另存。
只关闭视图用 Ctrl-W q（小写 `q`）；停止后台任务用任务列表里的 Ctrl-X，停止调试用 Shift-F5。

### 编辑、格式化与未保存文件

| 想做的事 | 按键 / 命令 |
|---|---|
| 选择 / 接受补全候选 | Ctrl-N / Ctrl-P；回车或 Ctrl-Y 接受，Ctrl-E 关闭 |
| 在代码片段字段之间移动 | Tab / Shift-Tab；字段里也能继续补全 |
| 看当前调用的参数签名 | 输入调用时自动提示；普通模式 `gK`、插入模式 Ctrl-K 手动查看 |
| 按语法单元扩大 / 缩小选区 | Ctrl-Space 进入语法选择；再按 Ctrl-Space 扩大，退格缩小，Esc 退出 |
| 注释当前行 / 已选文本 | `gcc` / 选择后 `gc` |
| 上移 / 下移当前行或选区 | Alt-K / Alt-J |
| 撤销 / 重做当前文件编辑 | `u` / Ctrl-R；`<leader>su` 查看撤销历史 |
| 当前行的错误和警告详情 | `<leader>cd` |
| 前一个 / 后一个诊断 | `[d` / `]d`；只看错误用 `[e` / `]e` |
| 按工程风格格式化当前文件 | `<leader>cf` |
| 只格式化选区 | 用 `v` / `V` 选择后 `<leader>cf`；块选区不支持 |
| 明确使用内置 UE 风格 | `:UEFormat epic`；选区用 `:'<,'>UEFormat epic` |
| 开 / 关参数名、推导类型提示 | `<leader>uh`（只切当前缓冲区） |
| 看全部未保存文件 | `:UEUnsaved`，或命令中枢搜「未保存」 |
| 退出前处理未保存文件 | `<leader>qq` / `:UEQuit` |

语法选区需要当前文件已有 Tree-sitter parser；picker 输入框里的 Ctrl-Space 是多选候选，
两处按键按当前界面分别生效。

C/C++ 会向文件的父目录查找 `.clang-format` 或 `_clang-format`。没有时提示
「本工程没有 .clang-format，已跳过」，可选择用内置 UE 风格格式化当前文件或已选文本，
也可取消。不会偷偷使用 LLVM 默认风格，不会替工程创建配置。UE 模板采用新行大括号、
4 列 tab 缩进并保留 include 顺序；它是本仓模板，不是 Epic 发布的官方配置。
clang-format 可能把选区扩展到所在语法单元，格式化后可用 `u` 撤销。
自动格式化仍默认关闭；`<leader>uf` 是已有的开关。

普通 clangd 缓冲区默认显示内联提示。若感觉阅读或滚动受影响，用 `<leader>uh` 关闭；
原有超大文件保护继续生效。

需要逐条处理错误时：先按 `]e` 到下一个错误，再按 `<leader>cd` 读完整说明；
需要修复建议时用 `<leader>ca`，能提供文本修改的建议会先显示预览。
参数签名和代码操作需要当前语言服务器提供能力。

### 逐项处理问题

| 想做的事 | 按键 / 入口 |
|---|---|
| 展开全部已提供的语言诊断 | `<leader>xx`；命令中心搜「全部文件错误」 |
| 只看当前文件的诊断 | `<leader>xX`；命令中心搜「当前文件错误」 |
| 按文字、文件名搜索诊断 | `<leader>sd`；命令中心搜「搜索错误」 |
| 在当前文件定位下一项 | `]d` / `[d`，只看 error 用 `]e` / `[e` |
| 打开当前 quickfix 结果 | 命令中心搜「当前结果列表」；前后用 `]q` / `[q` |

在 Trouble 诊断列表里用 `j` / `k` 选择、回车打开源码；`gb` 切当前文件筛选，`s` 切严重级别。
全部／当前文件入口共用同一诊断视图，再次执行会关闭它。切换范围时先关闭，
然后从要检查的源码窗口重新打开对应入口。
在源码按 `<leader>cd` 看详情，按 `<leader>ca` 查看当前语言服务提供的修复；修改后重新查看诊断。
跳到源码后用 Ctrl-O 返回。列表只显示语言服务已提供的诊断；空列表不等于整个工程已编译通过。
构建、搜索和崩溃的 quickfix 结果独立于这些诊断，命令中心分别列出两个入口。

普通撤销历史用 `<leader>su`，或在命令中心搜「当前文件撤销历史」；回车应用所选状态，
仍需自行保存。重构的整批回退另用 `:UERefactorUndo`。跳转位置用 `<leader>sj`，
书签用 `<leader>sm`；也可在命令中心搜「跳转位置」「书签」。

退出面板列出全部未保存缓冲区，可「保存全部并退出」「逐个查看」「放弃修改并退出」或取消；
放弃会再次确认，按 `y` 放弃、`n` 或回车取消；确认期间新增、编辑或重命名文件会取消退出，
让你重新检查。直接选文件也会取消退出并打开它。未命名、只读、无法写入或特殊缓冲区
会阻止保存后退出，原内容保留；先逐个处理，再次退出即可。直接 `:q` / `:qa` 仍沿用
Neovim 原生逐文件确认，`:qa!` 是明确放弃修改的原生命令；集中列表走上述退出入口。

### 回到工作现场

`:Restart` 先检查未保存文件；取消不创建新实例。未命名或不可写文件需先单独处理。
大于自动恢复限制的会话会提示手动入口：`:UESessionRestore` 默认只加载当前文件，其余按需打开；
有未保存内容时先处理。`:UESessionRestore full` 是显式完整恢复，可能启动更多解析。
自动恢复仍保持 24 文件、最多一个新增标签页的保护；按需检查最多 256 项、1 MiB。

异常退出后，`:UERecovery` 把本工程快照恢复到新的未命名缓冲区，原文件和已打开的新内容保留；
`:UERecovery all` 查看其他工程。状态栏有「可恢复文本」时可进入此入口。
普通文本修改约 1.5 秒合并写入一次；每份最多 2 MiB、每进程会话最多 64 个缓冲区，
旧的已退出实例记录按七天保留策略清理。超限或写入失败会显示「恢复缓存未更新」。
默认只扫描当前工程，排除正常退出及仍运行的实例；历史优先最近 session。每轮至多 128 份快照、
每目录 256 项，达到上限显示「扫描受限」，原快照保留。
最后尚未落盘的编辑及物理断电后的耐久性未保证；会话文件只保存工作布局，不代替文本快照。

## 7. 状态栏怎么读

右侧的 UE 段从左到右：

```
UE  <模块范围>  PROJECT  <索引状态>  Q:…  PREP*  <构建结果>  A:<设备>/<包名>  ⏵N
```

| 片段 | 含义 |
|---|---|
| 索引状态 | 索引是否就绪、是否在收敛 |
| `Q:…` | 排队中的索引任务 |
| `PREP*` | `:UEPrepare` 正在跑 |
| `BOK` / `B<数字>` / `BERR` | 最近一次构建成功 / 退出码 / 启动失败 |
| `LOOP✓ 42s` / `LOOP✗` | 最近一次一键循环成功及耗时 / 失败 |
| `A:Pixel 8/game` | Android 当前设备和包名（`no-device` 表示还没选） |
| `⏵3` | 有 3 个后台任务在跑，`<leader>X` 查看或停止 |

左侧模式块后面的 `⏸ DBG` / `▶ DBG` 表示调试会话停在断点 / 正在运行。
`未保存:3` 表示有 3 个缓冲区尚未保存，全部保存后消失。
`可恢复文本:N` 表示启动时发现本工程异常退出的文本快照；`恢复缓存未更新` 表示某份快照未写成。

启动时的 `维护诊断:N未读（可忽略）` 是给维护者的诊断记录，普通使用可忽略。
维护者用 `:UEProbeReport` 查看；查看只标记已读，不代表问题已解决。
默认仅在状态栏显示必要摘要，不弹内部日志。维护者可在自己的配置中设置
`require("ue.config").setup({ probe = { startup_notice = "notify" } })` 切回 INFO 通知，
默认值为 `"statusline"`。未读记录按 report-first 规格每会话保留提示，不能静默关闭。

## 8. 后台任务

构建、索引和日志读取可在后台运行；从列表查看或显式停止。

| 按键 | 作用 |
|---|---|
| `<leader>X` | 底部任务列表，`<CR>` / `dd` 停止选中任务，`r` 刷新 |
| `<leader>Xs` | 停止一个（只有一个时直接停） |
| `<leader>XA` | 全部停止（会先确认） |

### 关闭窗口后找回来

`<C-w>q` 关闭的是视图。找不到原文件、终端、结果或日志时，用 `<leader>wM` / `:UEWorkspace`：

| 列表里的分类 | 回车做什么 |
|---|---|
| `Windows` 窗口 | 聚焦已有窗口，包括其它标签页 |
| `Buffers` 隐藏缓冲区 | 重新显示仍保留的文件和未保存内容 |
| `Results` 结果 | 打开选择的搜索、构建或旧 quickfix 列表 |
| `Tasks` 任务 | 打开保留输出；没有输出时查看任务列表 |
| `Logs` 日志 | 找回仍保留的终端或日志缓冲区 |

可以输入文字筛选，也可直接用 `:UEWorkspace buffers` / `results` / `tasks` / `logs`。
Ctrl-R 刷新当前列表；Ctrl-X 只停止选中的已登记后台任务，调试停止仍用 Shift-F5。
关闭文件或输出窗口不会停止任务、重跑任务或丢弃未保存内容。缓冲区已删除、日志已淘汰或
窗口内容已改变时会说明原因；过期条目可先 Ctrl-R 刷新。

例如在构建输出里按了 Ctrl-W q：按空格、`w`、大写 `M`，输入任务名或 `Logs`，选中条目回车即可找回。
如果只是想回到某个文件，输入文件名，优先选 `Windows` 聚焦已有窗口，或选 `Buffers` 重新显示。
需要停止任务时才按 Ctrl-X；终端里的空格 `wM` 也能打开同一个入口。

### 共用底部面板

`<leader>uJ` 按 **构建输出 → 问题（quickfix）→ logcat → 后台任务** 循环；在构建终端里也能按。
四项复用同一个底部窗口，切换时不叠窗口、不停止任务；构建结束的输出仍能回看。
`:UEPanel history` 或构建输出里的 `gH` 查看最近阶段日志，最多保留 16 份。
也可以在 `<leader>P` 搜对应面板，或执行 `:UEPanel build` / `quickfix` / `logcat` / `tasks` 直接切换。
问题列表保留原生回车跳源码；DAP logcat 保留 `gl` / `gx`。没有日志读取任务时会提示先用
`<leader>ug` 或 `<leader>d4` 打开，切换面板本身不会启动设备命令。

## 9. 出问题时先看哪里

1. **`:UEDoctor`** —— 工具、项目、平台、设备、包名是否齐全。
2. **`<leader>uk`** —— 刚失败的操作有没有现成修复。
3. **`:UEDAPPreflight`** —— 调试附加会卡在哪一层。
4. **`:UEIndexStatus`** —— 跳转不对、搜不到时看索引状态。
5. **`<leader>uN`** —— 翻回刚才一闪而过的提示。
6. **`:NvimCoreHealth`** —— 编辑器本身的基础功能体检。

常见情况：

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| 附加时提示进程没在运行 | 应用没启动 | `<leader>uk`（改用启动调试），或先 `<leader>ul` |
| 断点是空心的、不命中 | 符号和设备上的包不是同一次构建 | 重新 `<leader>us` + `<leader>uq`，或重装 APK |
| 状态栏显示 `A:no-device` | 这个窗口还没选设备 | `<leader>uu` → Device |
| 提示「所选设备未连接」 | 设备被拔掉/掉线，目标仍是原来那台 | 接回设备，或 `<leader>uk` 选另一台 |
| `gd` 提示索引未就绪 | 还没 Prepare 或正在索引 | 看状态栏；必要时 `:UEPrepare` |
| 搜索结果不全 | 范围、筛选、部分结果或索引状态 | 看搜索标题并收窄条件；确认索引过期后 `:UEBuildCsearch` |
| `<C-w>q` 后找不到文件或输出 | 视图已经关闭 | `<leader>wM` 找隐藏缓冲区、结果或日志 |

## 10. 这套东西的取舍

- **键盘优先**。不做可点击的工具栏和按钮；用「一个可搜索入口 + 状态栏常驻提示」代替。
- **能选就不让你打字**。设备、包名、平台都是列表选择。
- **失败说人话**。先说是哪一层的问题，再说怎么办，能一键修的给一键修。
- **不卡界面**。多等几秒可以接受，编辑器卡住不行。
