## 3. 本次工作归档

### 2026-10-04 — 固定结果与替换路由，补齐问题处理入口

**Task**

继续产品体验改进：修复实际操作里会改变范围的按键，补齐诊断、撤销与阅读入口，并同步操作手册。

**Implemented**

- `]q` / `[q` 固定当前原生 quickfix，支持计数；无关 Trouble 侧栏不再截走跳转。
- `<leader>sr` 保留当前文件／本次选区行范围替换，首次加载 GrugFar 后不漂移；保留显式 GrugFar 命令、原生确认和撤销。
- Hub 区分语言诊断与搜索／构建／崩溃结果，增加全部／当前诊断、搜索诊断、当前文件替换、普通撤销历史、跳转历史与书签。
- Hub 当前文件大纲保留语法树回退，工作区符号接受有相应能力的语言服务；C++ 关系与重构守卫保持。
- Hub 确认沿用原生 normal-mode 交接后再关闭，来源在非零列时也能执行动作并保留光标；不放宽新输入保护。
- 使用手册及两份速查补齐任务步骤、范围、确认、返回与撤销，纠正旧文档把 `sr` 写为跨文件替换；回归映射和轻量规格同步。

**Pitfalls / Gotchas**

- Lazy 首次加载会恢复插件 keys 声明，配置层覆写不足以保证最终映射；同时取消相应继承声明并验证实际加载后状态。
- Trouble 的无 mode `is_open()` 可选择诊断、符号或文件视图；仅判断 `qflist` 又会漏自定义 mode。全局 quickfix 导航保持原生列表语义。
- 当前 quickfix 可能已被搜索或崩溃结果切换，继续构建排错前须显式选择保留的构建结果。语言诊断只代表已提供的诊断。
- GrugFar 保持独立磁盘工具，不冒充本仓受保护的多文件重构或整批撤销。
- 新原生反例揭示此前 Hub 验收漏掉非零列：菜单关闭把延迟退出插入模式带回源码，光标左移使动作被拒绝。已修调用顺序，并补真实键盘正例、取消和新输入反例。
- 首轮完整回归为 2963/2965、2 failed、0 skipped；两个旧关闭测试的列表前置查询会模糊匹配完整路径，随机临时目录可使第二个文件也命中。精确选择实际 file 字段，不扩大等待时间或放宽原确认断言；该轮不计最终门禁。
