## 3. 本次工作归档

### 2026-10-04 — 当前文档逐次查找与编辑区复用

**Task**

继续对标 IDE 的编辑体验：查找未保存文字的准确位置、找回隐藏文件而不累加分屏、首尾移动保持输入状态。

**Implemented**

- `document_find.lua` / `document_find_process.lua` 提供内存文档逐次匹配，包含未命名及未保存文本；`sf` / `sF` 与 Hub 接同一入口。
- 字面量、大小写、整词和单行正则条件可见；异步单线程 rg stdin，来源变更需刷新，旧坐标及取消后的结果不能跳转。
- Workspace Ctrl-O 在打开列表的普通编辑区显示隐藏文件，保留未保存文本和窗口数量；Enter 保持既有恢复方式。
- `line_move.lua` 在返回原生移动按键前核验首尾和计数，越界保留模式、光标及选区；合法移动与缩进保留原生撤销。
- 操作手册、速查、回归映射和知识库同步；保持现有模糊行浏览、磁盘文件搜索与索引入口。

**Pitfalls / Gotchas**

- 原生行筛选按行返回且使用模糊 matcher；同一行多次命中并非多项，已打开文件搜索读取磁盘会遗漏当前未保存文字。
- rg 的一条 JSON 可包含很多 submatches，结果条数和总输出预算不能代替单记录解码预算；stdin 保留每个逻辑行的换行。
- 零长度命中明确标为不支持，不能伪造 UTF-8 字节位置或显示为无结果。
- Workspace 新分屏恢复适合保留原视图；复用编辑区是显式 Ctrl-O，日志与结果仍走各自恢复入口。
- 新查询输入和 finder 更新不同步，快速改词后回车必须核对实际输入，不能确认旧行；原生同包按键反例已补永久回归。
- 原生 API 与 Ex 切换都会覆盖回调里的新选择；窗口复用只否决本次赋值，保留嵌套用户动作，不能靠换成 Ex 或事后回拉。
- 恢复 picker 重新捕获当前来源；关闭后清除自身引用环。集成首轮 27/28 的 GC 红灯另由默认 LuaJIT 缓存持有闭环：同一失败样本清自身表／原生恢复表仍为 2，JIT 缓存对照为 0。引用环测试在隔离原生子进程的解释执行环境检查，生产 JIT 与其它功能／响应性用例保持原样；不以缓存对照宣称生产实例立即回收。
