## 1. 固定现状证据（实测数字，避免凭感觉设计）

- [x] 1.1 记录被动模式盲区：`reset` 后连续三次 `busy()` 得到 `nil / nil / 19.7%` ——
      首次可用读数需 2 次采样 + ≥MIN_INTERVAL 间隔。
- [x] 1.2 记录该盲区的危险后果：`_admission.lua:61` 对 `nil` 返回 `true, "load-unknown"`（放行）
      → **最需要节流的那一刻恰好放行**。规则本身对（不能因测不出而永久停摆），
      错在感知层此刻处于冷态。
- [x] 1.3 记录采样开销（本机 24 核）：`uv.cpu_info()` **0.698 ms**、
      `snapshot()` **0.515 ms**（分配 24 个 table）、`busy()` 命中节流 0.00007 ms、
      `uv.getrusage()` **0.0019 ms**（便宜 ~270 倍）。
- [x] 1.4 记录归属边界：`cpu_info` 只给整机、`getrusage` 只给 Neovim 本进程且**不含仍在运行的
      子进程**；差值只能叫 `unattributed`，不得伪装成「外部进程占用」。

## 2. 常驻采样

- [x] 2.1 低频常驻计时器维护忙碌度；fast-event 安全（只做算术 + 必要时 `vim.schedule`）。
- [x] 2.2 采样分层：高频用便宜的 `getrusage`（自身占用），低频用 `cpu_info`（整机）。
- [x] 2.3 headless / 无 UI 时不常驻（对齐 `stall_probe` 由 UIEnter 启动的做法）。
- [x] 2.4 启动位置遵守 C3 启动顺序；不得在 `init.lua` 引入阻塞。

## 3. 读数语义

- [x] 3.1 暴露：整机忙碌度、自身占用、平滑值、趋势方向、`unknown` 状态。
- [x] 3.2 `unknown` 与 `idle` 严格区分；计数器回退/未推进 → `unknown`，不得返回 0。
- [x] 3.3 MUST NOT 使用 `uv.loadavg()`（Windows 恒 0）。
- [x] 3.4 纯函数化差分与趋势计算，便于注入测试。

## 4. 感知层不含策略

- [x] 4.1 移除/避免感知层内的任何阈值、推迟上限、降级动作。
- [x] 4.2 `_admission` 继续持有阈值，改为消费新读数（含自身占用与趋势）。
- [x] 4.3 用例：扫描感知层实现，出现水位/推迟/降级字样即 FAIL。
