# git-review-workspace Specification

## Purpose

定义编辑器内统一 Git 审阅工作区的用户行为大方向：在完整文件上下文中浏览并精确处理改动，
区分工作区、暂存区和历史版本，连续完成搜索、审阅与提交，并在大仓和外部并发修改场景中保护
数据与交互响应。原 Git 状态侧栏能力已收敛进本工作区，不再维护独立视图；Diffview 等专项工具
保留为按需入口，不属于本 spec 管辖的删除范围。

## Requirements

### Requirement: 默认以完整文件审阅改动，操作范围精确且不覆盖并发修改

工作区 SHALL 在一个界面提供文件列表及完整文件双栏（默认展开未改区域），Changes/Staged/
Conflicts/未跟踪文件均可发现，不得以局部 patch 代替正文。系统 SHALL 区分 hunk 与整文件操作
并按当前比较对象执行：暂存只改变 index，取消暂存保留工作区，历史比较不提供含糊的工作区写
操作。写操作 SHALL 基于当前文件/index 状态；已失效的审阅快照 MUST NOT 覆盖其他进程的新修改，
未保存 buffer SHALL 被保护，不允许隐式保存、丢弃或静默使用不同内容。

#### Scenario: 精确暂存与外部并发修改共存

- **WHEN** 一个文件有两个未暂存 hunk，用户暂存其中一个；同时其他进程修改了同一文件的 index
- **THEN** 仅所选 hunk 进入 index，另一个仍未暂存，工作区与未保存 buffer 不被自动改变
- **AND** 后续写操作基于已刷新状态正确执行，或拒绝并提示刷新，外部新增的其他暂存改动不丢失

### Requirement: Git 操作交接保持仓库上下文，历史/内容搜索保持原有语义

审阅、提交管理和搜索结果 SHALL 使用明确一致的仓库上下文（多仓库场景不因 cwd 而串仓）；用户
完成或取消提交流程后 SHALL 返回原审阅位置，不自动 push。系统 SHALL 提供文件/仓库历史、选中
行范围追溯、指定版本/分支比较和改动内容查询；改动内容查询 SHALL 保持 `git log -G --pickaxe-all`
的语义（区分内容正则匹配与字符串计数变化），不得被消息查询替代；比较版本 MUST NOT 触发
checkout 或修改工作区/index。

#### Scenario: 跨仓库操作与内容搜索语义

- **WHEN** 用户从仓库 A 的审阅进入提交管理（cwd 位于仓库 B），或对匹配正则但字符串计数未变的
  提交做改动内容搜索
- **THEN** 提交管理操作仓库 A 并在完成后返回 A 的审阅位置
- **AND** 内容搜索命中该提交，纯消息匹配而补丁不匹配的提交不命中

### Requirement: 用户入口收敛且专项能力保留，依赖缺失明确失败

默认审阅 SHALL 使用一个完整文件主界面，不再提供独立 Git 状态侧栏或终端 Git 默认入口；既有
Diffview SHALL 保留为明确按需入口，不因默认界面切换被删除或自动同时打开。提交、分支、stash、
rebase、reflog、全文 blame、历史版本 buffer 与 quickfix 历史能力 SHALL 仍有明确入口。审阅所需
的本地原生组件 SHALL 在明确的安装步骤准备并匹配版本/平台；正常打开审阅时 MUST NOT 静默下载
组件或把初始化失败呈现为空仓。

#### Scenario: 专项工具保留且原生组件缺失时不静默降级

- **WHEN** 用户主动使用 Diffview，或所需原生组件缺失/架构错误/与已锁定插件不匹配
- **THEN** Diffview 对应审阅、关闭、行历史仍可用，且不被自动重定向为默认工具
- **AND** 组件问题显示可诊断错误与修复入口，不联网安装、不修改工作区

### Requirement: 性能切换基于同覆盖实测，不得靠缩小数据集通过验收

切换默认入口前 SHALL 在相同覆盖和可比负载下记录旧界面与候选的延迟及资源证据（冷/暖缓存、
Git 查询与界面计算区分），不得以隐藏 untracked 或缩小数据集通过验收；真实仓库存在独立并发
写入时不能冻结输入，须核对 tracked 列表/index/被测文件字节未变后才按可比覆盖报告。

#### Scenario: 大仓验收与并发写入下的可比性

- **WHEN** 在同一仓库进行冷启动及多次暖缓存测量，且测量期间其他工作新增未跟踪文件
- **THEN** 报告打开/切文件/跳 hunk 的延迟分布及主循环延迟、CPU、RSS 等资源证据
- **AND** 只有确认差异为独立新增、无删除/过滤/漏项时才按可比覆盖报告，不称为相同或冻结输入；
  性能门禁失败或缺证据时不得宣称切换验收完成

## 选型与踩坑

- **选型**：默认审阅收敛为单一完整文件界面而非维护独立 Git 状态侧栏，理由是减少重复入口与
  状态不一致风险；Diffview 保留而非删除，因为部分工作流（如逐 hunk 历史）仍依赖其原生能力。
- **踩坑**：消费 Git porcelain 输出时若不使用 NUL 分隔记录，含空格/重命名的路径会被错误解析；
  处置为按 NUL 分隔消费，保留原始路径及 rename/copy 语义。
- **重要事项**：性能切换验收要求同覆盖对比，历史上曾出现靠缩小数据集或隐藏 untracked 文件
  制造有利数字的风险，因此该项验收流程被写为强约束而非建议。
