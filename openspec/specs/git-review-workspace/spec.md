# git-review-workspace Specification

## Purpose

定义编辑器内统一 Git 审阅工作区的用户行为：在完整文件上下文中浏览并精确处理改动，区分工作区、暂存区和历史版本，连续完成搜索、审阅与提交，并在大仓和外部并发修改场景中保护数据与交互响应。

## Requirements

### Requirement: 默认以完整文件审阅改动

工作区 SHALL 在一个审阅界面提供文件列表及完整文件双栏，默认展开未改区域；Changes、Staged、Conflicts 与未跟踪文件 SHALL 可发现，不得以局部 patch 代替正文。

#### Scenario: 从改动文件进入全文
- **WHEN** 用户选择一个包含两个相距较远 hunk 的文件
- **THEN** 两侧完整内容可滚动和搜索，两个 hunk 之间的未改正文仍可见
- **AND** 文件内 hunk 跳转与文件间切换均无需切换工具

#### Scenario: 文件覆盖和不可文本比较对象
- **WHEN** 仓库同时存在已跟踪修改、新增未跟踪文件、删除文件和二进制文件
- **THEN** 每项均可发现，二进制或无法显示的内容有明确状态
- **AND** 不以隐藏文件或空白 diff 假装无变化

### Requirement: 暂存操作具有精确且可区分的范围

系统 SHALL 区分 hunk 与整文件操作，并按当前比较对象执行；暂存 SHALL 只改变 index，取消暂存 SHALL 保留工作区，历史比较 SHALL 不提供含糊的工作区写操作。

#### Scenario: 仅暂存一个 hunk
- **WHEN** 一个文件有两个未暂存 hunk，用户暂存其中一个
- **THEN** `git diff --cached` 仅包含所选 hunk，另一个仍未暂存
- **AND** 工作区与未保存 buffer 内容不被自动保存或改变

#### Scenario: 取消暂存与工作区独立
- **WHEN** 一个文件同时存在 staged 和 unstaged 改动，用户在暂存视图取消暂存一个 hunk
- **THEN** index 仅移除指定改动，工作区字节及未保存内容保持不变

#### Scenario: 丢弃确认及取消
- **WHEN** 用户请求丢弃 hunk 或整个文件
- **THEN** 界面明确显示仓库、路径和操作范围并要求确认
- **AND** 用户取消时工作区、index 和 buffer 均保持不变

#### Scenario: 删除类及行尾边界
- **WHEN** 对纯删除、首尾行、CRLF 或无末尾换行文件执行支持的 hunk 操作
- **THEN** 结果与目标 Git patch 一致，未选区域及行尾不被顺带修改
- **AND** 不支持的操作明确拒绝且保持原数据

### Requirement: 并发更新与未保存内容不得被旧视图覆盖

写操作 SHALL 基于当前文件及 index 状态；已失效的审阅快照 MUST NOT 覆盖其他进程的新修改。未保存 buffer SHALL 被保护，不允许隐式保存、丢弃或静默使用不同内容。

上述快照范围校验针对 hunk 操作。明确标识的整文件暂存/取消暂存 SHALL 使用操作时的整个磁盘/index 版本；整文件丢弃 SHALL 确认后重新检查脏 buffer。它们不是旧视图快照的逐 hunk 应用，也不承诺与外部 Git 进程之间的原子事务。发现未保存 buffer 时 SHALL 拒绝写入并提示处理。

#### Scenario: 外部更新暂存区
- **WHEN** 审阅打开后其他进程修改同一文件的 index，用户再执行原视图中的写操作
- **THEN** 操作要么基于已刷新状态正确执行，要么拒绝并提示刷新后重新操作
- **AND** 外部新增的其他暂存改动保持不变

#### Scenario: 磁盘变化时 buffer 有未保存修改
- **WHEN** 磁盘版本变化且当前编辑 buffer 仍脏
- **THEN** 刷新不覆盖或保存脏 buffer，操作明确区分比较来源
- **AND** 无法保证范围正确时拒绝写操作而不猜测用户意图

### Requirement: Git 操作交接保持仓库和审阅位置

审阅、提交管理和搜索结果 SHALL 使用明确且一致的仓库上下文；用户完成或取消提交流程后 SHALL 返回原审阅位置或可解释的相邻条目，不自动 push。

#### Scenario: 两个仓库与虚拟 buffer
- **WHEN** 用户从仓库 A 的审阅虚拟 buffer 进入提交管理，而 cwd 位于仓库 B
- **THEN** 管理界面操作仓库 A，返回时仍定位 A 的文件

#### Scenario: 关闭和重复进入
- **WHEN** 用户重复打开同仓库审阅或关闭审阅
- **THEN** 重复打开聚焦已有工作区，关闭恢复原编辑位置
- **AND** 不留下本次审阅启动的后台任务或 watcher

### Requirement: 历史和改动内容搜索保持原有语义

系统 SHALL 提供文件/仓库历史、选中行范围追溯、指定版本/分支比较和改动内容查询；查询结果进入完整文件审阅。改动内容查询 SHALL 保持 `git log -G --pickaxe-all` 的语义，不得被消息查询或字符串计数查询替代。

#### Scenario: 区分内容正则与字符串计数
- **WHEN** 某提交修改了匹配正则的代码行但匹配字符串出现次数未变
- **THEN** 改动内容搜索能够命中该提交
- **AND** 仅提交消息匹配而补丁不匹配的提交不会因此命中

#### Scenario: 当前文件和行范围追溯
- **WHEN** 用户对重命名后的文件或本次 Visual 选中行查询历史
- **THEN** 文件追溯保留可用的重命名历史，行范围查询使用本次选择
- **AND** 选择结果进入所选提交的完整文件比较，不静默扩大成整个仓库的历史

#### Scenario: 比较版本不改变工作区
- **WHEN** 用户比较两个 ref、根提交或 merge commit
- **THEN** 两侧来源明确，merge commit 的父版本明确，根提交正确处理空前态
- **AND** 不执行 checkout，不修改工作区或 index

### Requirement: 用户入口收敛且专项能力保留

默认审阅 SHALL 使用一个完整文件主界面，不再提供独立 Git 状态侧栏或终端 Git 默认入口；既有 Diffview SHALL 保留为明确的按需入口，不因默认界面切换而被删除或自动同时打开。提交、分支、stash、rebase、reflog、全文 blame、历史版本 buffer 与 quickfix 历史能力 SHALL 仍有明确入口。用户在编辑器之外的 Git 工具不属于删除范围。

#### Scenario: 启动后的最终入口
- **WHEN** 插件加载和 buffer 附加完成后检查 Git 菜单与有效键位
- **THEN** 默认审阅/状态选择进入默认界面，已删除的重复入口不复活
- **AND** 暂存快捷键不会与内容搜索形成前缀竞争

#### Scenario: 主动使用熟悉的 Diffview
- **WHEN** 用户通过 `<leader>gv/gV`、Visual `<leader>gv` 或 Diffview 原生命令使用原工具
- **THEN** 对应审阅、关闭、行历史仍可使用
- **AND** 既不自动重定向为默认工具，也不关闭另一个工具中用户主动打开的审阅

#### Scenario: 专项工具与其他侧栏
- **WHEN** 用户执行全文 blame、打开 staged 版本 buffer、查看 quickfix 历史或 buffers/TODO 侧栏
- **THEN** 对应专项能力仍可用，未因删除重复 Git UI 而消失
- **AND** 宿主原有 Git CLI 和用户配置保持不变

### Requirement: 依赖缺失明确失败且运行不隐式安装

审阅所需的本地组件 SHALL 在明确的安装步骤准备并匹配版本/平台；正常打开审阅时 MUST NOT 静默下载组件或把初始化失败呈现为空仓。

#### Scenario: 原生组件缺失或不匹配
- **WHEN** 所需原生组件缺失、架构错误或与已锁定插件不匹配
- **THEN** 显示可诊断的错误与修复入口，不联网安装、不修改工作区

### Requirement: 性能切换基于同覆盖实测

切换默认入口前 SHALL 在相同覆盖和可比负载下记录旧界面与候选的延迟及资源证据，区分冷/暖缓存、Git 查询与界面计算；不得以隐藏 untracked 或缩小数据集通过验收。

#### Scenario: 代表性大仓验收
- **WHEN** 在同一仓库输入上进行冷启动及每动作至少 20 次暖缓存测量
- **THEN** 报告打开、切文件、跳 hunk 的 p50/p95，以及主循环延迟、CPU、RSS、Git 子进程数量
- **AND** 暖打开和切文件 p95 不超过旧基线 1.2 倍；hunk 跳转 p95 不超过 `max(旧基线 × 1.2, 2ms)`。20ms 心跳额外延迟 p95 不超过 50ms，且无本次接线导致的超过 100ms 同步停顿

#### Scenario: 真实仓库存在独立并发写入
- **WHEN** 测量期间其他工作新增未跟踪文件，不能冻结仓库输入
- **THEN** 逐次记录完整文件覆盖及私有清单差异，核对 tracked 列表、index 和被测文件字节未变
- **AND** 只有确认差异为独立新增、没有删除/过滤/漏项时，才按可比覆盖报告打开耗时并披露限制，不称为相同或冻结输入
- **AND** 不停止其他工作、不修改或隐藏数据来制造相同输入；稳定目标上的切文件和 hunk 动作单独判断

#### Scenario: 空闲与退出
- **WHEN** 活跃审阅空闲 60 秒后关闭
- **THEN** 不出现 Git 子进程自激循环，关闭后审阅拥有的后台活动归零
- **AND** 性能门禁失败或缺少真实工程证据时不得宣称切换验收完成
